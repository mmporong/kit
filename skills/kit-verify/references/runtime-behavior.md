# 성공 응답 뒤 실제 결과 확인

저장·API·집계 기능이 있을 때 필요한 항목만 확인합니다. 새 도구 설치나 모든 사례의 일괄 실행을 요구하지 않습니다.
현재 과제의 완료 조건과 KIT.md가 우선입니다. 허용된 로컬 API·순수 로직 검사로 확인하고 브라우저·화면 자동 조작은 실행하지 않습니다.

## 입력에서 결과까지

- 실제 진입점에서 입력이 처리 코드와 결과까지 이어지는지 봅니다. 별도 데모 함수만 실행한 결과는 해당 진입점의 증거가 아닙니다.
- 문서에서 기대값을 구할 수 있는 서로 다른 작은 입력을 고릅니다. 결과에 영향을 주는 값 하나를 바꾸고 예상한 결과가 바뀌는지 확인합니다. 결과가 같아야 하는 변경은 그 불변 조건을 확인합니다.
- 화면·응답의 상수, 임시 배열, mock, 캐시가 요구된 데이터 처리를 대신하지 않는지 추적합니다. 시연 데이터는 표시하고 실데이터 검증과 구분합니다.
- 결과가 같다는 이유만으로 고정 출력이라고 단정하지 않습니다. 입력이 전달됐는지, 캐시 기준이 맞는지, 업무 규칙상 같은 결과인지 확인합니다.
- API 응답은 상태코드뿐 아니라 본문·식별자·필드 값·부작용을 확인합니다. `200`이나 `success: true`만으로 통과시키지 않습니다.

## 저장이 요구될 때

1. 원본을 보존한 임시 저장소나 기존 테스트 격리 기능에서 식별 가능한 작은 값을 저장합니다. 운영 데이터나 원본 과제 파일을 시험용으로 변경하지 않습니다.
2. 쓰기 응답에 되돌아온 값만 보지 말고, 별도 읽기 요청이나 새 저장소 연결로 같은 식별자의 값을 조회합니다. 쓰기에 사용한 메모리 객체를 읽는 검사는 저장 확인이 아닙니다.
3. 영속성이 요구되면 격리한 테스트 인스턴스의 새 프로세스에서도 같은 저장소를 읽어 값이 남는지 확인합니다. 사용자 작업 서버를 임의로 재시작하지 않습니다. 이 검사가 불가능하면 재시작 후 보존은 미확인으로 둡니다.
4. 수정·삭제·중복 처리 중 명시된 기능만 같은 방법으로 확인합니다. 중복 요청의 기대 결과는 과제 규칙을 따르며 멱등성을 임의로 요구하지 않습니다.
5. 테스트 데이터·프로세스를 정리하고 정리 결과를 남깁니다. 격리를 보장할 수 없으면 쓰기 검사를 보류하고 이유와 읽기 전용 확인 범위를 기록합니다.

## 실패가 성공처럼 보이지 않는지

- 명시된 입력 규칙을 위반한 사례를 한 개 선택해 오류 응답과 저장 상태를 확인합니다. 오류를 삼킨 뒤 성공 문구를 반환하거나, 실패했는데 일부 상태만 남기는지 봅니다.
- 빈 결과·데이터 없음·파싱 오류·연결 실패를 정상적인 0건·0%와 구분합니다. 사용할 수 없는 연동을 임의의 성공 데이터로 대체하지 않습니다.
- 실패 유발은 격리된 테스트 범위에서만 합니다. 운영 연결을 끊거나 자격증명·권한을 변경하지 않습니다.

## 파일로 내보낸 결과

생성 명령의 종료만 확인하지 말고 산출물을 새로 열어 필수 컬럼·행 수·식별자·계산값을 원본 또는 독립적인 작은 기대값과 비교합니다. 파일 존재나 크기만으로 계산 성공을 판단하지 않습니다.

## 화면이 필요한 확인

사용자에게 입력값, 조작 순서, 기대 결과를 짧게 안내합니다. 예: 값을 저장하고 새로고침한 다음 같은 항목이 남는지 확인하기. API·저장 검사가 통과했어도 화면 연결은 사용자 회신 전까지 미확인입니다.

## 기록

기존 검증 기록에 `입력과 기대값 근거 / 실행 진입점 / 실제 응답 / 별도 조회 또는 산출물 / 판정 / 미확인 범위`만 추가합니다. 단위 테스트 통과를 화면·영속성·전체 흐름 통과로 확대하지 않습니다.

이 문서는 일반적인 기능 검증 절차를 이 키트에 맞게 새로 작성한 지침입니다. 자동 검사기나 실제 시험 결과가 아닙니다.
