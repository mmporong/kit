# 선택형 검증 기록 양식

빈 양식은 실행 이력이나 완료 증거가 아닙니다. 과제의 지정 양식이 있으면 그것을 사용합니다.
필요한 항목만 기존 기록에 추가하고, 같은 결과를 여러 문서에 반복 저장하지 않습니다.

## 요구와 결정
요구 / 근거 위치 / 선택과 이유 / 기각한 대안(실제로 검토한 경우만) / 미확정 사항.

## 검사 1건
- 조건 ID 또는 완료 기준:
- 검사 시각과 시간대 / 작업 위치:
- 관련 소스·테스트·설정·의존성·입력과 식별 정보:
- 커밋·버전 / 미커밋 변경 여부 / 필요한 경우 선택 파일의 해시:
- 실제 실행 명령 / 종료코드:
- 테스트 러너인 경우 수집·실행·통과·실패·오류·건너뜀 수:
- 기대 결과와 그 근거:
- 실제 결과 / 작업공간 내부 stdout·stderr 또는 관련 로그 위치:
- 출력 잘림·상충하는 요약·해석하지 못한 부분:
- 판정: 통과 / 실패 / 미확인. 부분 통과는 확인한 범위만 명시:

테스트 0개·전부 건너뜀·TODO-only는 기능 검증 통과가 아닙니다.
빌드·계산 등 테스트 러너가 아닌 검사는 테스트 수 대신 산출물과 기대 결과를 확인합니다.
러너가 제공하지 않은 집계는 미확인/해당 없음으로 두고 수치를 만들지 않습니다.

## 변경 후 재사용 판단
- 이전 기록을 만든 이후 관련 파일·설정·입력 변경 여부:
- 확인 방법과 범위 / 비교하지 않은 의존성·외부 상태:
- 관련 검사를 다시 실행했는지 / 생략했다면 기존 근거가 유효한 이유:

커밋 번호만으로 미커밋 변경까지 확인한 것으로 쓰지 않습니다.
해시 일치는 선택한 파일의 동일성만 보여주며, 테스트 성공이나 전체 환경 동일성의 증거가 아닙니다.
자동 무효화·감시 기능은 없으므로 변경 여부가 불명확하면 현재 통과로 재사용하지 않습니다.

## 수정
실패 재현 / 원인 근거 / 변경 / 같은 검사 재실행 / 기존 정상 흐름 확인.

## 인계
실행 방법 / 현재 결과 / 해결되지 않은 문제 / 보장하지 못하는 범위.

로그·해시·판정은 허용된 작업공간 안에만 남깁니다. 자격증명·개인 메일·접속 링크를 수집하거나 외부로 전송하지 않습니다.
