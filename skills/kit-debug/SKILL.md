# 오류를 재현하고 필요한 곳만 수정

## 입력
재현 입력과 순서, 오류 메시지, 기대 결과, 실제 결과, 최근 변경. 민감값을 제거한 오류만 사용합니다.

## 처리
1. 동일 입력으로 재현하고 종료 코드·오류 위치·관련 파일을 확인합니다. 재현되지 않으면 부족한 관찰을 적습니다.
2. 최근 diff와 입력→검증→처리→저장→출력의 경계에서 어디가 처음 달라지는지 추적합니다.
3. 원인 가설 하나와 그 가설이 틀렸을 때의 관찰을 적고 가장 작은 검사를 실행합니다.
4. 여러 설정을 동시에 바꾸거나 관련 없는 리팩토링을 하지 않습니다.
5. 가능하면 실패를 검출하는 테스트를 먼저 실행한 뒤 최소 수정합니다.
6. 같은 실패 입력과 기존 정상 흐름을 재실행합니다. 회귀 테스트가 실제 결함을 잡는지 안전한 복사본에서 확인할 수 있습니다.
7. 반복 실패하면 같은 수정을 계속하지 않고 가설·증거를 다시 봅니다. 근거 없는 대규모 구조 변경은 중단합니다.
8. 플랫폼·감독·인증 장애는 사용자 코드 변경으로 우회하지 않고 제공된 문의 절차로 넘깁니다.

## 출력
재현 여부 / 최초 차이 / 원인과 근거 / 변경 파일 / 수정 후 동일 검사 / 남은 위험.
환경변수 전체, 키, 토큰, 인증 파일을 조사·출력하지 않습니다.


## 공통 경계
현재 과제 지침을 우선하고 KIT.md를 보조 원칙으로 사용합니다. 원문 데이터 보존, 외부 전송 금지, 설정 변경 금지, 미실행의 미확인 표시를 지킵니다. AI 사용 금지 단계에는 사용하지 않습니다.
